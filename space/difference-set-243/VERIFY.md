# VERIFY — how to reproduce every claim

All runs were made on 2026-10-04 on one x86-64 machine (WSL2, Linux 6.6), each job on one core under `systemd-run --scope -p MemoryMax=2G nice -n 15`. The times below are wall-clock times on that machine, which was shared with other jobs.

## Tools

| tool | source | version / commit |
|---|---|---|
| Python | 3.12 (standard library only for the scripts here) | |
| CaDiCaL | https://github.com/arminbiere/cadical | 3.0.1, commit c60730422e75 (2026-07-19) |
| drat-trim, lrat-check | https://github.com/marijnheule/drat-trim | commit 2e3b2dc0ecf9 (2024-11-25) |
| cake_lpr (verified LRAT/LPR checker) | https://github.com/tanyongkiam/cake_lpr | commit a36874a8b750 (2026-07-22); `cake_lpr.S` sha256 2f3af32d55083839b3fa0e693afd817679c0b8944bef41def05a8b0ec72b7d4a (matches the repo's `cake_lpr.sha256`) |

Build:

```sh
git clone https://github.com/arminbiere/cadical && (cd cadical && ./configure && make)
git clone https://github.com/marijnheule/drat-trim && (cd drat-trim && make)
git clone https://github.com/tanyongkiam/cake_lpr && (cd cake_lpr && make cake_lpr)
gcc -O2 -o enum_images enum_images.c
export CADICAL=$PWD/cadical/build/cadical
```

## Files in this folder

| file | what it does |
|---|---|
| `ds_cnf.py` | CNF generator for (v,k,λ) difference sets in any Z_{m1}×…×Z_{mr}, with a numerical multiplier, all cyclic quotients, and an optional fixed image in G/pG |
| `enum_images.c` | complete search for the images of D in G/3G ≅ Z₃³ (6¹³ plane-sum choices + direct check) |
| `orbit_check.py` | second, independent enumeration of the images; builds explicit automorphisms of G and checks that the 864 images form one orbit |
| `images864.txt` | the 864 images (one line of 27 counts each, sorted; line 1 is E₀) |
| `run_sweep.py` | builds and solves the CNF for each of the 864 images (symmetry-free check) |
| `check_model.py` | decodes a SAT model and checks the difference-set property by counting all differences |
| `plug_in.py` | fixes the variables to a known difference set (soundness test of the encoding) |
| `controls.sh` | control experiments with known answers |
| `known_sets.json` | two known difference sets from the La Jolla repository (used by `controls.sh`) |
| `reduction_checks.py` | brute-force recomputation of every number used in Steps 1–6 |
| `sweep864.log` | result of `run_sweep.py` on all 864 images |

## 1. Reduction checks

```sh
python3 -c "import ds_cnf as d; print(d.allowed_vectors(9,27,121,60,61,61%9)); print(d.allowed_vectors(3,81,121,60,61,1)); print(len(d.cyclic_quotients([3,9,9])))"
```
This prints the 12 admissible Z₉-images, the 6 admissible Z₃-images, and 49 (the number of cyclic quotients). The orbit count (99 orbits: 27 fixed points and 72 of size 3) is printed by every `ds_cnf.py` run.

## 2. The 864 images (two independent enumerations) and the orbit claim

```sh
./enum_images > images_c.txt          # complete search
sort images_c.txt | cmp - images864.txt
python3 orbit_check.py images864.txt
```
Output (`enum_images`, 1017 s):
```
Z3-quotient images: 6: (36,40,45) (36,45,40) (40,36,45) (40,45,36) (45,36,40) (45,40,36)
inversion formula sum_d P_d(d.x) = 9 f(x) + 4 sum f: ok on 1000 random f
search nodes 15603491635, integral candidates 221184, rejected by direct check 0, distinct images 864
```
"Integral candidates" are all images that satisfy the difference-set conditions in G/3G, so there are 221 184 without the multiplier condition. 864 of them satisfy E(x) ≡ 0 (mod 3) off the line L.

Output (`orbit_check.py`, 17 s):
```
enum_images.c: 864 images (864 distinct), all pass direct check: True
second enumeration: 864 images; identical sets: True
group generated by 40 random automorphisms + translation by e1, acting on G/3G: order 2592
generators map the image set into itself: True
orbits on the image set: 1, sizes [864]
representative (lexicographically smallest) E0 = [3, 3, 3, 3, 3, 6, 3, 6, 6, 4, 3, 6, 6, 3, 3, 3, 6, 6, 6, 6, 6, 6, 3, 3, 6, 3, 6]
stabilizer order of E0 in the group: 3
```
`sha256(images864.txt)` is given in the checksum table below.

`python3 reduction_checks.py` prints `ALL OK` for the 12 brute-force facts used in Steps 1–6. These are the multiplier-theorem conditions, the orbit structure, the fact that each orbit lies in one coset of 3G, the 13 + 36 = 49 cyclic quotients, the 6 admissible Z₃-images, and the 12 admissible Z₉-images, the last found by a brute-force search different from the one in `ds_cnf.py`.

## 3. Main instance (image fixed to E₀) and certificates

```sh
python3 ds_cnf.py --moduli 3,9,9 --v 243 --k 121 --lam 60 --t 61 --fix-p 3 \
  --fix-image "[$(head -1 images864.txt | tr ' ' ,)]" --out e0.cnf --meta e0.json
$CADICAL --lrat --binary=false e0.cnf e0.lrat          # LRAT certificate
cake_lpr/cake_lpr e0.cnf e0.lrat                       # verified checker
drat-trim/lrat-check e0.cnf e0.lrat
$CADICAL --binary=false e0.cnf e0.drat                 # DRAT certificate
drat-trim/drat-trim e0.cnf e0.drat
```
| step | result | time |
|---|---|---|
| `ds_cnf.py` | 65 723 variables, 679 495 clauses | 1.2 s |
| CaDiCaL (plain) | `s UNSATISFIABLE` | 8–11 s |
| CaDiCaL `--lrat` | UNSAT; LRAT 26 955 793 bytes | 11 s |
| cake_lpr | **`s VERIFIED UNSAT`** | 3.7 s, 1.6 GB |
| lrat-check | `c VERIFIED` | 0.8 s |
| CaDiCaL (DRAT) | UNSAT; DRAT 16 246 842 bytes | 12 s |
| drat-trim | `s VERIFIED` (13 452 of 342 165 lemmas in core) | 4–5 s |

cake_lpr's default heap is 4 GB. To keep it inside the 2 GB memory limit, it was run as `cake_lpr --CML_HEAP_SIZE=1536 --CML_STACK_SIZE=256 …`. These flags are read by cake_lpr's own C wrapper and set only the memory sizes.

The certificates are not stored in the repository. They can be regenerated with the commands above. CaDiCaL is deterministic for a fixed version and input, but a rebuilt certificate need not be byte-identical, so the sha256 values are given only to identify the files that were checked.

## 4. Symmetry-free check: all 864 images

```sh
python3 run_sweep.py images864.txt sweep.log --cadical $CADICAL
```
Run as two workers (`--start 0 --step 2` and `--start 1 --step 2`), each on one core. The combined log is `sweep864.log`, with one line per image: index, status, solver seconds.

- 864 of 864 images: `UNSATISFIABLE`
- solver time per image 6.3–24.4 s (generation adds about 1–3 s); total solver time 10 726 s (about 3.0 h)
- These runs are not certified individually. They exist to remove the dependence on Step 7, not to replace the certificate in §5.

The plug-in rows test soundness of the encoding directly. When the variables are fixed to a genuine difference set, every clause can be satisfied. This is exactly the property the nonexistence proof depends on.

The case Z₃ × Z₃ × Z₃ × Z₉ is harder for this encoding than the target group. The multiplier has 81 fixed points there (135 orbits against 99), and the group has more symmetry. A run that is not decided cannot contradict the known answer. For the soundness direction the proof depends on, the plug-in tests and the decided controls give the evidence.

A scratch-only attempt to split that control by its images in G/3G ≅ Z₃⁴ (all-solutions enumeration with PySAT) did not finish within 20 minutes and is not included.
